# 发布前功能与实体补全

基线：`29c2fc35793c350d0a4451770836db5c943d60b4`，`0.2.0-rc.4`。

2026-09-06 用户接受以下实施方案。本文件区分已接受设计与已执行验证；未填写结果的门禁仍未完成。

## 范围与裁定

- 累计量原始单位由用户确认为 `mGy/mSv`；保留当前数值、单位和既有历史，撤回此前只改微单位标签的建议。保留手册/UI 矛盾，不提升为新实机物理量证据。
- 动态谱图支持 1024、2048、4096 道。A0/A1 没有总道数字段，按每个辐射通道显式配置道数；旧配置默认 2048，不根据首段、静默时间或计数值猜测结束。
- 原始实体 ID、设备信息页中的主型号/硬件/主固件，以及现有默认启用的协处理器固件 sensor 保留。
- 增加默认启用的 3 个状态 sensor、6 个状态 binary_sensor，以及每个已安装通道的谱图累积 binary_sensor；只读状态不依赖设备控制开关。
- A6 新增 34 个普通只读实体，与原有 7 个合计 41 个业务字段；数组按系数顺序展开，字段不丢入大块 JSON 属性。所有校准实体无长期统计 state class。
- 剂量显示提供原始/微单位选择；微单位为对应原始值乘 1000，不改变 Gy/Sv 物理量类别。协议、内部缓存、原始诊断保持原始值；CPS、累计时间、校准系数不换算。
- 单位方案选择独立微单位实体：真实 HA 2026.7.4 核心统计处理函数实测确认 `mSv/h` 与 `µSv/h` 没有对应转换器，同实体混合单位会进入不稳定单位处理。原始实体的 ID、单位和历史始终保留，微单位选项增加独立固定微单位实体，不把原实体改为新单位。完整 Recorder 启动因本地可选依赖/初始化问题尚未完成，以下核心函数验证不冒充端到端记录测试。
- A4 脉冲流、0x64 校准写入、串口、科创云仍不实现；整体 `hardware_verified=false` 不变。

## 2026-09-06 HA 统计单位兼容性

在开发环境安装的真实 Home Assistant `2026.7.4` 中调用 `homeassistant.components.sensor.recorder._normalize_states`，使用合成状态验证实际核心处理逻辑：

| 输入 | 结果 |
| --- | --- |
| 原始实体始终使用 `mSv/h` | 正常归一化 |
| 同一实体历史混用 `mSv/h` 与 `µSv/h` | 返回空结果，登记 `sensor_warn_unstable_unit` |
| 独立原始/微单位实体各自保持固定单位 | 两者正常归一化 |
| 同一实体恢复为原始单位的测试窗口 | 可恢复处理；不能据此宣称跨单位窗口统计连续 |

验证产物保存在忽略目录 `private/recorder-unit-check-20260906/`，不包含真实设备历史。该实验没有启动完整 HA/SQLite Recorder，也没有改动测试机配置、数据库或设备连接；它证明默认原始实体上直接切换单位不安全，足以选择独立换算实体。它不证明用户历史已迁移，也不构成真实测量或长期运行证据。

### 本轮只读边界异常

后续诊断发现实机条目的既有 `time_sync_enabled`、设备控制与破坏性操作选项均开启。HA 重启后自动执行一次设备时间同步：`controls.commands=1`，最近同步时间落在本次启动窗口。这违反了本轮只读部署约束，不能因选项是部署前已有或没有人工点写按钮而记作“无写命令”。部署前没有检查并处理这些写入选项，是本次流程遗漏。
