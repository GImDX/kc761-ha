# KC761 测试与发布计划

适用当前 rc9 开发候选及后续经授权的发布。本文是门禁计划，不是已完成结果；当前阶段见 [实施记录](PRE_RELEASE_COVERAGE.md)。开发版本号不自动决定最终发布类型、tag 或分支名。

## 1. 环境边界

| 环境 | 允许 | 禁止 |
| --- | --- | --- |
| 开发工作树 | 实现、静态检查、模拟器、文档、构建 | 把模拟结果写成实机证据 |
| 隔离测试 HA | 安装候选、模拟器、只读真实设备回归、重载/重启/回滚 | 未授权真实设备写入；保存凭据到仓库 |
| 生产 HA | 仅安装已通过门禁的固定版本 | RC 探索、独立探针、协议写入、直接覆盖开发文件 |

测试凭据、完整设备 ID、部署地址、原始帧和候选包保存在私有目录；公开仓库只记录脱敏结论与哈希。

## 2. 本地自动化门禁

每个候选提交至少运行：

1. Ruff；
2. 所有 JSON 解析与 Python compileall；
3. Node `--check` 和 `tests/frontend_card_contract.mjs`；
4. 全量 pytest，综合覆盖率与独立分支覆盖率均不低于 95%；生成 coverage JSON 后运行 `tests/check_branch_coverage.py`，缺失、无效或不足阈值的报告必须失败，不能用综合百分比代替分支百分比；
5. `pip check`；
6. `git diff --check` 和公开文档隐私扫描。

协议测试覆盖分片、粘包、异常 BAG_LEN、未知 FLAG、SYNC 回卷、迟到响应、半帧 EOF、A0/A1 重组、BLE 通知队列和写 ACK。HA 测试覆盖 Config Flow、reconfigure、options 归一化、实体集合、控制门禁、WebSocket、诊断、卸载/重载/停止和谱图存档。

## 3. GitHub CI 门禁

发布分支推送后必须通过同一 workflow 的：

- Python 3.14 安装及固定测试依赖；
- Ruff、JSON、compileall；
- Node 24 前端语法与契约；
- pytest 综合覆盖率 ≥95%，并用 `tests/check_branch_coverage.py` 单独验证分支覆盖率 ≥95%；
- 官方 Hassfest；
- HACS integration validation。

所有 GitHub Actions 使用完整不可变 commit SHA。任何失败都先在发布分支修复并新增原子提交；不得通过跳过测试、降低覆盖率或改写历史伪造绿灯。

## 4. 模拟器回归

至少验证：

- 正常设备、未知兼容型号、不同传感器组合；
- A3/A1 自动上传完整轮次、乱序、重复、缺片、冲突和断线重置；
- TCP 分片/粘包、延迟、EOF、迟到帧和 100 次重连；
- NaN/Inf、电池越界、非 ASCII/非法 ID；
- 默认门禁下绝不收到 `0x62/0x63/0x66`，永不收到 `0x64`；
- 两层门禁启用后只允许白名单字段、值域和逐通道 clear mask；
- 保存/加载/索引重建/损坏文件跳过/256 条保留上限。

模拟器可以验证软件行为，不能确认设备端序、单位、ACK 真实行为或长期稳定性。

本地长时/重连验收入口（从仓库根目录执行，使用已验证的项目虚拟环境）：

```powershell
& '.\.venv\Scripts\python.exe' -m tests.simulator_soak --duration-seconds 600 --reconnects 100 --output 'private\simulator-soak.json'
```

该入口只允许 loopback IP 字面量并启动本地模拟器，不接受真实设备地址；检查实际运行时间、完成重连次数、禁止命令和资源清理，失败时返回非零。它补充上述分片、组帧、异常和存档回归，不替代全部协议测试，也不是测试 HA 或真实设备的 24 小时验收。

## 5. 测试 HA 验收

用 HACS/标准 Config Flow 安装，不直接编辑 `.storage`。候选部署前后记录源码包 SHA-256，测试结束不清理配置和日志。

### 必查

- TCP/BLE 传输步骤只显示本传输需要的字段；BLE 地址选择器可看到 HA 广播缓存并保留手动值；
- 条目只拥有一条活动连接，重配置失败不会丢失旧端点；
- 设备信息、已安装通道实体和结构化谱图可用；未安装通道不创建；
- 原始剂量实体与新增 History 数值固定 mGy/mSv（含 `/h`）；旧 `_micro` 不再产生新数值，历史不改写，查询起点携带的旧状态须排除后再统计新增记录；
- Options Flow 无单位项和手动道数项；自动候选长度、实际点数与卡片/存档/CSV 一致，保留观测/推断依据，1024/4096 软件测试不冒充实机验证；
- 谱图卡自动出现在卡片选择器，普通视图能选择历史谱图；
- ROI/Data cursor/缩放刷新后保留，Ctrl+滚轮缩放，线性/对数设置持久；
- 能量轴默认与复位视窗从 0 keV 开始；手动 Ctrl+滚轮缩小可回到实际 CH0 并跨刷新保留，不改写原始标定或 ROI；
- Ctrl 横向、Shift 纵向缩放以绘图区光标为锚点，线性/对数均覆盖；双击绘图区复位双轴，纵轴刻度长度受限且不截断原始数据精度；
- 采谱忙态仍可打开 Configure；构建指纹应同时核对实际 HTTP 内容与刷新后的卡片实例，不以版本号或服务器文件哈希单独证明页面已更新；
- 游标交互流畅，数据变化仍触发完整重绘；
- 断开后实体 unavailable，恢复后 available；
- unload、reload、HA restart 后无残留任务或重复连接；
- 默认无控制实体/清空入口，手动开启门禁后集合符合 [ENTITY_MODEL.md](ENTITY_MODEL.md)；
- 日志无 KC761 integration exception，诊断中无 host、完整 ID、原始帧或谱图点阵。

### 稳定性

- 模拟器至少 10 分钟运行观察和 100 次重连；
- 真实设备只读回归保持单客户端所有权；
- 稳定版前对目标传输完成至少 24 小时运行；RC 可发布但必须明确该门禁是否尚未完成。

当前 rc9 的第 4 项稳定性验收于 2026-09-08 按用户调整的标准确认通过：用户确认测试容器已连续运行数日，接受不再额外等待完整的 24 小时定时观察。此为本候选的验收决定，不改变上述稳定版的一般要求，也不声称已采集完整连续时序；12 条既有样本及约 38 分 50 秒缺口保留，观察任务已暂停，详见 [实施记录](PRE_RELEASE_COVERAGE.md)。

## 6. 真实设备证据

当前 RC 只允许既有 HA 集成路径进行真实设备只读回归，不同时启动独立探针。必须分别记录：

- 型号、硬件/主固件/协处理器版本（公开记录脱敏）；
- TCP/BLE 端点可达与 DEVICE_ID 一致性；
- A2/A5/A6、A0、A3/A1 的实际字段和交错；
- 官方上位机或设备显示的同步对照；
- 运行时长、断线/恢复和多客户端限制。

自动上传按手册 §3.3 区分流模式与谱模式：低计数率下验证 A3/A4 接收，高计数率越过设备内部未公开阈值才验证 A3/A1 谱模式；上位机不能指定格式。未触发 A1 不单独构成缺陷，记为该条件未验证。流模式成帧接收也不代表已实现 A4 脉冲语义解析或增量谱图。当前候选第 4 项已由用户按此结论整体验收，未测硬件条件继续公开。

若验证写操作，必须使用专门测试设备、逐命令授权、完整 ACK/读回/断电恢复记录。既有自动校时仍属于写入：授权保留该行为的部署必须如实记录，不能描述为零写入，也不据此通过其它控制或清空门禁。默认发布检查不授权人工真实设备写入。

## 7. 发布步骤

本轮授权检查点（2026-09-09）：第 5 项已整体验收，用户授权自主推进到 Release 草稿供确认，并补充授权提交两份收尾文档后推进 `main`。可准备候选、推送候选分支运行 CI、在同一候选提交全绿且可快进时推进 `main`、创建 draft prerelease；不强制推送、不公开发布、不部署生产。以下完整发布步骤中的公开 tag/Release 收尾须待草稿确认及相应授权，草稿完成不等于 RC 已发布。

1. 在独立发布工作树完成实现、测试、文档和二次审查；
2. 每一阶段只暂存命名文件并创建原子提交；
3. 确认 author/committer 都是当前 GitHub 账号的 noreply 地址；
4. 与用户确认最终版本、发布类型和目标分支后，仅推送已授权分支并等待全部 CI；
5. 仅在 CI 通过后，把 `main` 快进到相同提交并推送；
6. 仅按该次授权创建目标 tag 和 GitHub Release，二者必须指向同一 commit；RC 应为 prerelease，不将开发候选自动提升为 stable；
7. stable 发布需另行确认完整门禁与授权，不部署生产 HA。

## 8. 回滚

- Git：保留上一候选提交、旧验证分支和历史 PR，不强制改写历史；
- HACS：重新下载上一个已知良好 prerelease/stable 版本并重启 HA；
- 配置：不删除 Config Entry 或谱图存档，旧条目缺失 `transport` 仍按 TCP 加载；
- 失败测试栈：停止候选容器但保留配置、日志和包哈希，不执行 Docker 全局清理。

## 9. RC 退出条件

只有以下全部满足才宣布用户确认的目标版本已发布：

- 本地和远端所有软件门禁通过；
- 发布分支/main/tag/release commit 一致；
- 仓库不含部署地址、凭据、完整设备 ID、原始捕获或私有路径；
- Release 明确 `hardware_verified=false`、写入默认关闭和所有剩余硬件门禁；
- 工作树干净，生产环境未被修改。
