# 测试、发布与部署计划

状态：初始执行计划

日期：2026-08-10

当前 RC 的离线验证记录见 [RC_TEST_RESULTS.md](RC_TEST_RESULTS.md)。真实设备 L 级验证、隔离测试 Home Assistant 联调和正式部署门禁仍未完成。

## 1. 环境边界

| 环境 | 角色 | 允许的工作 | 禁止的工作 |
| --- | --- | --- | --- |
| 开发机 | Git、实现、静态检查、fixture 单测 | 文档、协议代码、HA 适配、离线测试 | 冒充真实设备结果 |
| 测试 Home Assistant | 测试环境 | 只读联调、故障注入、受控写验证、升级/回滚 | 未备份的破坏性测试、生产数据假设 |
| 正式 Home Assistant | 正式环境 | 安装固定发布版本、只读验收、监控 | 协议探索、开发目录直拷、未测试升级 |

本阶段没有连接、修改或重启两个远端环境。

## 2. 里程碑

### M0 - 文档与 Git 基线

完成条件：

- Git 仓库以 `main` 为初始分支；
- 原始手册和截图纳入证据清单并记录 SHA-256；
- 架构、协议证据、实体模型、决策和测试计划完整；
- 没有 `custom_components` 实现代码；
- 测试和正式环境没有任何写入。

### M1 - 只读协议核心

目标：建立与 Home Assistant 无关的 TCP 帧解析和只读命令客户端。

范围：

- 固定长度响应：ACK、STATUS、DEVICE_INFO、CAL_DATA；
- 可变长度响应：MC_DATA、STREAM_DATA；
- TCP 分片、粘包、未知前缀、缓冲上限和重同步；
- SYNC 分配、超时、迟到帧和自动上传分流；
- 不发送任何设置或清除命令。

门禁：

- 所有解析由具备来源元数据的 fixture 覆盖；
- 对每种多字节类型有端序证据；
- FP16 与官方显示值对齐；
- 异常长度和畸形帧不会造成无限内存增长；
- 所有测试离线可复现。

### M2 - 测试环境只读集成

目标：在测试 Home Assistant 安装最小只读 HA 集成。

范围：

- Config Flow、unique ID、reconfigure；
- 单一 Coordinator 和持久 TCP 连接；
- 默认实体与脱敏 diagnostics；
- 配置条目加载、卸载、重载和 HA 重启恢复；
- 不注册控制实体和高风险 action。

门禁：

- 首次配置能识别真实 DEVICE_ID；
- 同一设备不能重复添加；
- 修改地址只通过 reconfigure，且拒绝指向不同 DEVICE_ID；
- 连续运行不少于 24 小时，无读循环泄漏、任务残留或持续重连；
- 断网、设备重启和 HA 重启均能恢复；
- 实体值与设备屏幕/官方上位机在定义允许的时间差内一致；
- 未发送 `0x62`、`0x63`、`0x64`、`0x66`。

### M3 - 谱图实验功能

目标：完成谱图读取和按需返回，不进入 Recorder。

前置条件：

- 真实设备确认总道数、片段顺序、最后包和 `0xFFFF` 语义；
- 三种 `MC_DATA_SOURCE` 至少覆盖设备实际安装通道；
- 丢片、重复片、乱序和超时行为有测试。

门禁：

- 完整谱图重组与官方上位机一致；
- 缺片时明确失败，不返回静默损坏的数组；
- 默认不轮询，不写实体属性和 Recorder；
- 响应大小、并发和超时有上限。

### M4 - 可选设备控制

目标：只增加经过验证、可读回、可回滚的低风险控制。

候选顺序：

1. 音量和声音/灯光开关；
2. 传感器选择；
3. 手动同步设备时间。

每项单独满足：

- Options Flow 默认关闭；
- 字段白名单和值域；
- 0xFF 跳过或读-改-写不覆盖无关字段；
- ACK 状态与回显命令验证；
- 立即读回；
- 官方上位机并发时行为可解释；
- 测试环境成功和失败路径都有 fixture/日志。

校准写入和清除统计不随 M4 自动进入范围。

### M5 - HACS 发布候选

目标：形成可重复安装的 release candidate。

门禁：

- 仓库只有一个 `custom_components/kc761` 集成；
- 运行文件全部位于集成目录；
- `hacs.json`、`manifest.json`、README、翻译和 diagnostics 完整；
- 当前 Home Assistant Hassfest 与 HACS validation 通过；
- Ruff、pytest、JSON/翻译检查和 Python 编译通过；
- 干净 HA 实例安装、升级、降级和删除验证通过；
- release tag 与 manifest version 一致；
- 发布说明列出兼容型号、固件证据、已知限制和回滚方法。

### M6 - 正式环境部署

目标：把在测试环境验收过的固定 release 部署到正式 Home Assistant。

门禁：

- 正式环境当前 HA 版本和安装方式已只读核对；
- 已备份 `/config` 中将被覆盖的集成目录和相关配置条目数据；
- 使用 release tag/zip，不使用开发工作区；
- 部署前记录当前版本、文件哈希和回滚包；
- 部署后检查 HA HTTP 就绪、配置条目加载、实体更新和错误日志；
- 观察期无异常后才删除临时部署文件，备份按用户授权保留。

## 3. 协议测试矩阵

| 类别 | 必测场景 |
| --- | --- |
| 固定帧 | 6、81、100、150 字节完整帧；逐字节分片；多帧粘包 |
| 可变帧 | N=0、最小/最大 N、声明长度不符、尾部缺失、超长 |
| 同步 | SYNC 0x00、0xFF 回卷、多请求、迟到响应、未知 SYNC |
| 自动上传 | 关闭；已开启流模式；已开启谱模式；与查询响应交错 |
| 数值 | 正/负温度、通道 -1、0 值、正常值、NaN/Inf、边界值 |
| 版本 | 已知型号 10-14、未知型号、不同主/协处理器版本 |
| 谱图 | 多包、最后包填充、倍率、缺包、重复、乱序、来源切换 |
| 恢复 | TCP EOF、连接拒绝、读超时、半帧断线、设备重启 |

## 4. Home Assistant 测试矩阵

| 范围 | 验收项 |
| --- | --- |
| Config Flow | 成功、无法连接、无法识别、未知型号、重复设备 |
| Reconfigure | 地址更新成功、DEVICE_ID 不匹配拒绝、资源关闭 |
| Setup | 首次刷新成功、ConfigEntryNotReady、重试后恢复 |
| Entities | 安装通道动态创建、未运行通道 unknown、默认启用策略 |
| Availability | 失败变 unavailable、恢复后可用、缓存不伪装新数据 |
| Lifecycle | unload 无残留任务、reload 单连接、HA stop 幂等关闭 |
| Diagnostics | host/完整 ID/原始帧脱敏，错误计数可用 |
| Recorder | 5 秒默认负载可接受，完整谱图不入库 |
| Translations | 简体中文和英文 key 对齐，无硬编码 UI 文本 |

## 5. 实机只读验证步骤

首次接触真实设备遵循以下顺序：

1. 记录设备屏幕可见型号、固件和当前运行传感器。
2. 只读确认 TCP 地址和端口，不修改设备网络设置。
3. 发送一次设备信息读取，保存原始应答并立即断开。
4. 对照官方上位机和设备屏幕验证字段，不执行设置。
5. 再建立持久连接，以最低必要频率读取状态。
6. 观察设备自动上传当前状态，不主动开启或关闭。
7. 官方上位机同时连接时，仅观察并发读取行为。
8. 验证完成后形成脱敏 fixture、证据表和测试，而不是只留聊天结论。

原始抓包只保存在开发/测试证据目录，不进入 diagnostics；提交仓库前必须脱敏设备 ID 和网络地址。

## 6. 故障注入

测试环境至少执行：

- 阻断设备 TCP 端口后恢复；
- 在接收半帧时断开连接；
- 设备重启；
- Home Assistant 重启；
- 配置条目 reload/unload；
- 修改为不可达地址，再 reconfigure 回正确地址；
- 官方上位机连接/断开；
- 自动上传已开启时运行 HA 轮询；
- 高频测量期间观察谱模式切换，但不人为制造辐射源风险。

不得为了测试对设备实施不安全辐射暴露或未经授权的校准/清除操作。

## 7. 部署与回滚

### 7.1 测试环境

1. 记录当前 HA 版本、安装方式和已有同名目录。
2. 备份现有 `custom_components/kc761`（若存在）。
3. 安装固定构建，核对文件 SHA-256。
4. 重启或 reload 后检查实际 HA 就绪端点，而不是只看容器运行状态。
5. 验证配置流、实体、日志、重连和卸载。
6. 回滚时恢复原目录/删除新目录并恢复配置，重新验证 HA 就绪。

### 7.2 正式环境

流程与测试环境相同，但只允许使用已经验收的 release，并记录：

- 旧版、新版和 tag；
- 安装包 SHA-256；
- 备份路径；
- 部署前后日志摘要；
- 回滚命令或步骤；
- 验收时间和结果。

不运行广泛 Docker 清理，不删除 `/config`、历史数据库、备份或 HACS 数据。

## 8. 发布策略

- `main` 保持可发布；开发使用短生命周期分支。
- 版本遵循语义化版本。
- 首个只读预发布使用 `0.1.0` 系列；协议/实体语义稳定前避免 `1.0.0`。
- 每个 GitHub release 固定集成版本和兼容说明。
- HACS 安装优先使用 GitHub release；默认分支仅作为开发/预览入口。
- 不在未经用户请求时推送仓库或创建 GitHub 远端。

## 9. 退出条件

正式版本必须能回答并以证据支持：

- 连接的是哪台设备，unique ID 如何保证稳定？
- 每个多字节字段使用什么端序，依据是什么？
- FP16 如何编码，剂量和累计量单位是什么？
- 断线、半帧、迟到帧和自动上传交错如何处理？
- 哪些命令会写设备，默认是否可能触发？
- 谱图是否进入 Recorder？
- 测试环境执行了哪些版本、故障和回滚验证？
- 正式环境如何恢复到部署前状态？

任何一项不能回答时，对应功能不能进入正式环境。
