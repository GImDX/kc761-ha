## 2. 适用设备与接口

手册明确适用于：

- KC761A；
- KC761B；
- KC761C；
- KC761CN。

手册称 BLE、局域网和科创云三种通信方式可以同时使用，设备执行所有到达的指令。这意味着集成不能假设自己独占设备状态；官方上位机、蓝牙客户端和 HA 可能相互改变传感器选择、灯光、音量、自动上传或校准参数。

### 2.1 局域网

- 物理接口为 RJ45，支持 PoE 802.3af/802.3at。
- 使用 TCP/IP。
- 局域网连接时，辐射计是服务端。
- 手册没有写 TCP 端口。
- 官方上位机截图将端口预填为 `7601`；这是 U 级证据，等待实机确认。

### 2.2 BLE

- BLE 5.0，GATT，设备为服务端。
- 接口类似 Nordic UART Service。
- RX 特征：`6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，属性 `write`。
- TX 特征：`6E400003-B5A3-F393-E0A9-E50E24DCCA9E`，属性 `notify`。
- 手册未给出服务 UUID，不能直接假定标准 NUS 服务 UUID。
- 最大 MTU 517；有效 payload 为 MTU-3。
- 设备选择 182、504 字节两档 BLE 最大包长；MTU 小于 185 时不应答。
- 订阅 TX 后，设备默认开启 BLE 自动上传，并在首帧以谱模式推送。

BLE 通知允许丢包，手册建议通过后续同步或重复读取补齐。该恢复模型在局域网首版完成前不实现。

### 2.3 云连接

- 明文传输。
- 云下行命令和设备上行数据末尾追加 32 字节校验码。
- 自建云目前不支持；手册只描述全零或忽略校验的兼容行为。
- 设备连接云后会周期发送 8 字节包，直到收到任意格式正确的指令。

本项目不实现云连接。

### 2.4 串口

官方上位机设备添加窗口有“串口”选项，但本手册没有串口物理层、波特率、校验、包边界或连接角色定义。串口不进入任何实现承诺。

## 3. 指令与响应总表

### 3.1 主动指令

| 命令 | 值 | 请求长度 | 响应 | 首版状态 |
| --- | ---: | ---: | --- | --- |
| `CMD_GET_MC_DATA` | `0x52` | 5 | 一个或多个 `MC_DATA` | 协议层预留；HA 默认不开启 |
| `CMD_GET_STA` | `0x53` | 4 | `STATUS_DATA` | 首版核心只读命令 |
| `CMD_GET_DEVICE_INFO` | `0x54` | 4 | `DEVICE_INFO` | 首版核心只读命令 |
| `CMD_GET_CAL_DATA` | `0x55` | 4 | `CAL_DATA` | 开发诊断候选，不周期读取 |
| `CMD_SET_STA` | `0x62` | 8 | `CMD_ACK` | 首版禁止 |
| `CMD_SET_DEVICE_TIME` | `0x63` | 8 | `CMD_ACK` | 首版禁止 |
| `CMD_SET_REVISED_DATA` | `0x64` | 65 | `CMD_ACK` | 高风险，首版禁止 |
| `CMD_SET_CLEAR` | `0x66` | 7 | `CMD_ACK` | 破坏性，首版禁止 |

请求结构没有通用长度字段，长度由命令类型确定；响应结构在字节 2-3 提供 `BAG_LEN`。

### 3.2 上行帧标志

| FLAG | 值 | 固定/可变长度 | 来源 |
| --- | ---: | --- | --- |
| `MC_DATA` 查询应答 | `0xA0` | `9 + 2N` | 主动读取谱图 |
| `MC_DATA` 自动上传 | `0xA1` | `9 + 2N` | 谱模式推送 |
| `STATUS_DATA` 查询应答 | `0xA2` | 81 | 主动读取状态 |
| `STATUS_DATA` 自动上传 | `0xA3` | 81 | 自动上传首帧 |
| `STREAM_DATA` | `0xA4` | `4 + 2N` | 流模式脉冲推送 |
| `DEVICE_INFO` | `0xA5` | 100 | 主动读取设备信息 |
| `CAL_DATA` | `0xA6` | 150 | 主动读取校准数据 |
| `CMD_ACK` | `0xAA` | 6 | 设置/清除应答 |

所有上行帧开头均为：1 字节 `SYNC`、1 字节 FLAG、2 字节 `BAG_LEN`。TCP 解析器必须以声明长度拆帧，而不是以 socket 读取次数拆帧。

## 4. 实时状态包

`STATUS_DATA` 总长 81 字节，包含：

| 字段组 | 线协议类型 | 语义 | 当前证据状态 |
| --- | --- | --- | --- |
| `RAD_SENSOR_STATUS` | `uint8` | 传感器选择、三个通道谱图累积位 | 手册确认 |
| `VOLUME_STATUS` | `uint8` | 全局音量、计数音、按键音、密集计数效果 | 手册确认 |
| `LED_SCREEN_STATUS` | `uint8` | 计数闪光、背光开关、背光亮度 | 手册确认 |
| `AUTO_UPLOAD_STATUS` | `uint8` | 0 关闭，1 开启 | 手册确认 |
| `BAT_PERCENT` | `uint8` | 电池百分比 | 手册确认；实机范围待验证 |
| `AIR_PRESSURE3BA` | `uint16` | 气压 hPa | 手册确认；字段名疑似历史命名 |
| `DEVICE_TEMP` | `int16` | 0.1 摄氏度 | 手册确认 |
| `DEVICE_TIME` | `time_t` 4 字节 | UNIX 时间戳 | 手册确认；时区显示策略待验证 |
| `RESERVE` | 16 字节 | 保留 | 必须跳过并保留长度检查 |
| 每通道 RAW CPS | `int32` | 上一秒计数率，关闭时 -1 | 手册确认 |
| 每通道 RAW 剂量率 | `FP16` | mGy/h，关闭时 -1 | FP16 编码待实机确认 |
| 每通道 RAW 剂量当量率 | `FP16` | mSv/h，关闭时 -1 | FP16 编码待实机确认 |
| 每通道 AVG CPS | `float` | 自适应窗口平滑计数率 | FP32 端序待实机确认 |
| 每通道 AVG 剂量率 | `FP16` | 平滑 mGy/h | FP16 编码待实机确认 |
| 每通道 AVG 剂量当量率 | `FP16` | 平滑 mSv/h | FP16 编码待实机确认 |

通道含义固定为：

- RAD0：伽玛；
- RAD1：中子；
- RAD2：PIN。

PIN 与其它传感器不能同时运行；有中子传感器的设备中，伽玛与中子绑定开启。读取到 `-1` 表示通道未运行，不是 0，也不是通信错误。

### 4.1 状态位

`RAD_SENSOR_STATUS`：

- bit 0-1：传感器选择，00 伽玛、01 中子、10 PIN；
- bit 2：RAD0 谱图累积；
- bit 3：RAD1 谱图累积；
- bit 4：RAD2 谱图累积。

`VOLUME_STATUS`：

- bit 0-1：全局音量，00 静音、01 小、10 大；
- bit 2：计数音；
- bit 3：按键音；
- bit 4：密集计数效果。

`LED_SCREEN_STATUS`：

- bit 0：计数闪光；
- bit 1：背光开关；
- bit 2：背光亮度，0 微亮、1 最亮；部分固件可能不支持调节。

## 5. 设备信息包

`DEVICE_INFO` 总长 100 字节，包含型号、版本、传感器型号、16 字节设备 ID，以及三个通道的谱图累积时间、剂量累积时间、累计剂量和累计剂量当量。

### 5.1 型号值

| 十进制值 | 型号 |
| ---: | --- |
| 10 | KC761 内测版 |
| 11 | KC761 正式版 |
| 12 | KC761A/B |
| 13 | KC761C |
| 14 | KC761CN |

### 5.2 版本换算

- `HW_VER`：十进制值除以 10，例如 12 -> V1.2。
- `FW_VER`、`CO_FW_VER`：十进制值除以 100，例如 180 -> V1.80。

直接用浮点除法格式化可能丢失尾随零；实现应按整数拆分生成版本文本。

### 5.3 传感器型号

| 索引 | 名称 | 测量对象 | 兼容型号 |
| ---: | --- | --- | --- |
| `0x00` | 无传感器 | 无 | 无 |
| `0x01` | KC7601.21 CsI | γ、β | KC761 内测版、KC761 |
| `0x02` | KC7601.24 CsI | γ、β | KC761A/B |
| `0x03` | KC7601.25 CsI | γ、β | KC761A/B |
| `0x04` | KC7601.26 CsI | γ、β | KC761C/CN |
| `0x05-0x07` | PIN | α、β、γ（低灵敏度） | 全系列 |
| `0x08` | KC7601.31 6Li | n、γ（低灵敏度） | KC761A/B/C/CN |

`DEVICE_ID` 为 16 字节稳定标识；公开记录只保留脱敏形式（例如 `7601-0000-******`）。实现必须处理 NUL 填充、ASCII 解码失败和未来格式变化，但不得用 IP 替代稳定 ID。

## 6. 谱图与自动上传

### 6.1 主动谱图

请求指定 `MC_DATA_SOURCE`：

- `0x00`：伽玛；
- `0x01`：中子；
- `0x02`：PIN。

响应片段包括：

- `MC_OFFSET`：首个道址；
- `MC_RATIO`：实际计数倍率，必须大于等于 1；
- 若干 16 位相对计数；实际计数为相对计数乘倍率。

手册给出 1024、2048、4096 三种总道数以及不同最大包长下的包数，但没有字段直接声明当前谱图总道数。最后一包超出实际范围的部分填 `0xFFFF`。

在实机确认前，不能把“遇到首个 0xFFFF”作为唯一终止规则，因为手册没有保证 `0xFFFF` 不会成为合法相对计数。需要通过设备型号、实际包序列、偏移规律和超时共同确认完成条件。

### 6.2 自动上传流模式

开启自动上传后每秒一轮。低计数率时首个网络数据块由 81 字节 `STATUS_DATA` 后接一个 `STREAM_DATA` 组成；脉冲多时还有后续 `STREAM_DATA` 帧。

每个 16 位 `PULSE`：

- 高 2 bit：数据源；
- 低 14 bit：道址。

首块中 N 最大 473，后续流帧 N 最大 512。高计数率时设备改为谱模式，流数据 N=0。

### 6.3 自动上传谱模式

一轮包含一个 FLAG=`0xA3` 的状态帧和一组 FLAG=`0xA1` 的谱图片段。每轮只上传当前选中的一张谱图；选中项可能被本机或其它上位机改变。

## 7. 校准数据

`CAL_DATA` 长 150 字节，包含工厂校准版本、能量缩放/偏移、触发阈值、剂量缩放、中子窗口、海拔偏移、自定义能量三次多项式和工厂分段能量多项式。

主要语义：

- 能量修正：`修正后能量 = ENERGY_ZOOM × 修正前能量 + ENERGY_OFFSET`。
- 自定义能量刻度为 `E(x) = ax³ + bx² + cx + d`。
- 2025 Q1 后设备通常使用三段工厂拟合；`FAC_CAL_VER=0x00` 单段，`0x02` 三段。
- 写校准支持全部字节为 `0xFF` 表示跳过对应字段。

由于字段存在文档矛盾，且错误校准会影响设备剂量计算，首版仅保留读取和离线解析研究，不提供写入口。

## 8. 已确认的资料矛盾与歧义

以下问题必须进入测试用例和实机验证记录：

| 编号 | 问题 | 风险 | 当前处理 |
| --- | --- | --- | --- |
| P-01 | 手册示例只明确设备时间采用字节倒序；其它 `uint16/int16/int32/float/FP16` 未总括端序 | 所有数值都可能解错 | 保存原始帧，以已知值逐字段验证 |
| P-02 | `FP16` 未说明是否为 IEEE 754 binary16 | 剂量率解码错误 | 用设备显示值和官方上位机值交叉验证 |
| P-03 | 累计量表格写 `uGy/uSv`，后文描述写 `mGy/mSv`，上位机按 `Gy/Sv` 显示 | 1000 或 1000000 倍单位错误 | 累计量实体默认禁用，确认缩放后再发布 |
| P-04 | 校准表字段为 `NEU_WINDOW_CENTER`，说明文字却持续写 `LOW/HIGH` 且要求前者小于后者 | 写错校准字段 | 不实现中子窗口写入 |
| P-05 | 时间、校准和清除 ACK 表把回显字段都命名为 `CMD_SET_STA`，值却分别为 0x63/0x64/0x66 | ACK 解析歧义 | 统一解释为 `ACK_COMMAND`，实机核对 |
| P-06 | 手册未声明 TCP 端口，上位机预填 7601 | 默认连接失败 | 端口可编辑，7601 仅作预填观察值 |
| P-07 | 手册封面写 V1.8，上位机提示某些 KC761 需固件 V1.81+ | 旧固件结构差异 | 配置时读取版本并记录，实机建立兼容矩阵 |
| P-08 | 上位机支持串口，手册无串口协议 | 错误承诺传输支持 | 首版排除串口 |
| P-09 | BLE 只给 RX/TX 特征，未给服务 UUID | 无法可靠发现服务 | BLE 延后，不假设标准 UUID |
| P-10 | 谱图总道数未在响应头中直接给出 | 无法严格判断重组完成 | 谱图不进入首版实体，先抓取完整序列 |
| P-11 | `BAG_LEN` 是否包含自身由表格可推得“包含”，但端序未明说 | 流解析失步 | fixture 覆盖固定长度 6/81/100/150 |
| P-12 | `NULL` 和 `RESERVE` 的未来固件取值未承诺 | 过严解析拒绝兼容帧 | 请求严格写规定值；响应保留字段不参与语义校验 |

## 10. 实机验证清单

测试环境开始写代码前后，按以下顺序形成 L 级证据：

1. 确认设备实际 IP、TCP 端口、固件/硬件版本和型号；不把截图地址当作真实地址。
2. 只读连接并保存 `GET_DEVICE_INFO`、`GET_STA` 的原始十六进制帧、时间戳和解析候选。
3. 将设备屏幕、官方上位机显示和原始帧对齐，确认多字节端序、FP32、FP16 和缩放。
4. 在设备时间设置为已知值的前提下，只读确认 `DEVICE_TIME` 端序与时区语义；不先执行写时钟。
5. 对三种传感器运行状态验证 `-1`、0 和有效测量值的区别。
6. 读取至少两轮设备信息，确认累计量变化速率和单位。
7. 在不改变设备自动上传设置的情况下，分别观察关闭和已开启状态；确认查询应答与推送交错。
8. 读取完整谱图，记录所有 `MC_OFFSET`、`MC_RATIO`、包长、总包数、填充值和完成条件。
9. 断开网络、重启设备、重启 HA、重新加载配置条目，验证资源关闭与恢复。
10. 与官方上位机同时连接，验证多客户端行为；不执行写操作。

只有第 2-7 项通过后，基础只读实体才可以进入测试发布；第 8 项通过后才评审谱图功能；任何写操作另设独立门禁。
