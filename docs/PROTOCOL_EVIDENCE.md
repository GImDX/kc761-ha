## 2. 适用设备与接口

手册明确适用于：

- KC761A；
- KC761B；
- KC761C；
- KC761CN。

手册称 BLE、局域网和科创云三种通信方式可以同时使用，设备执行所有到达的指令。这意味着集成不能假设自己独占设备状态；官方上位机、蓝牙客户端和 HA 可能相互改变传感器选择、灯光、音量、自动上传或校准参数。

### 2.1 局域网

- 物理接口为 RJ45，支持 PoE 802.3af/802.3at。
- 使用 TCP/IP。
- 局域网连接时，辐射计是服务端。
- 手册没有写 TCP 端口。
- 官方上位机截图将端口预填为 `7601`；一台隔离测试设备已在该候选端口完成 ARP 门控和只读应答，达到该设备的 L 级可达证据，但不能泛化为所有固件。

### 2.2 BLE

- BLE 5.0，GATT，设备为服务端。
- RX 特征：`6E400002-B5A3-F393-E0A9-E50E24DCCA9E`，属性 `write`。
- TX 特征：`6E400003-B5A3-F393-E0A9-E50E24DCCA9E`，属性 `notify`。
- 经授权实机连接确认服务 UUID 为 `59462f12-9543-9999-12c8-58b459a2712d`；该值仅作为本设备的默认服务约束，兼容固件可通过显式配置覆盖。
- 最大 MTU 517；有效 payload 为 MTU-3。
- 设备选择 182、504 字节两档 BLE 最大包长；MTU 小于 185 时不应答。
- 订阅 TX 后，设备默认开启 BLE 自动上传，并在首帧以谱模式推送。

BLE 通知允许丢包，手册建议通过后续同步或重复读取补齐。该恢复模型在局域网首版完成前不实现。

当前软件边界：Config Flow 只接受用户显式提供的 BLE address；连接复用 HA Bluetooth manager，不做独立扫描或无标识的自动发现。连接后的 GATT 服务表默认限定为上述已验证服务，并且必须包含唯一的 RX/TX 特征对；兼容固件只有在用户显式提供其它已验证 UUID 时才覆盖默认值。通知队列和协议帧解析均有界，队列溢出或请求超时会使连接失败并交由 Coordinator 重连。上述内容是软件设计/测试约束；MTU 协商、特征所属服务的跨固件一致性、丢包补读和长期稳定性仍需真实设备门禁。

## 4. 实时状态包

`STATUS_DATA` 总长 81 字节，包含：

| 字段组 | 线协议类型 | 语义 | 当前证据状态 |
| --- | --- | --- | --- |
| `RAD_SENSOR_STATUS` | `uint8` | 传感器选择、三个通道谱图累积位 | 手册确认 |
| `VOLUME_STATUS` | `uint8` | 全局音量、计数音、按键音、密集计数效果 | 手册确认 |
| `LED_SCREEN_STATUS` | `uint8` | 计数闪光、背光开关、背光亮度 | 手册确认 |
| `AUTO_UPLOAD_STATUS` | `uint8` | 0 关闭，1 开启 | 手册确认 |
| `BAT_PERCENT` | `uint8` | 低 7 位为电池百分比；bit 7 为未命名状态位 | 本设备 `0x80` 与 UI `0%` 连续对齐；高位具体语义待验证 |
| `AIR_PRESSURE3BA` | `uint16` | 气压 hPa | 手册确认；字段名疑似历史命名 |
| `DEVICE_TEMP` | `int16` | 0.1 摄氏度 | 手册确认 |
| `DEVICE_TIME` | `time_t` 4 字节 | UNIX 时间戳 | 手册确认；时区显示策略待验证 |
| `RESERVE` | 16 字节 | 保留 | 必须跳过并保留长度检查 |
| 每通道 RAW CPS | `int32` | 上一秒计数率，关闭时 -1 | 本设备已与官方 CSV 324/324 逐帧确认 |
| 每通道 RAW 剂量率 | `FP16` | mGy/h，关闭时 -1 | 本设备 binary16 解码有效；物理量未由独立导出列确认 |
| 每通道 RAW 剂量当量率 | `FP16` | mSv/h，关闭时 -1 | 本设备已确认小端 IEEE-754 binary16；乘 1000 与 UI/CSV µSv/h 一致 |
| 每通道 AVG CPS | `float` | 手册称自适应窗口平滑计数率 | 本设备 239/239 为 0；官方上位机平均值由本地 30 秒窗口计算；`KI-AVG-001` |
| 每通道 AVG 剂量率 | `FP16` | 手册称平滑 mGy/h | 本设备 239/239 为 0；作为已知设备返回值接受；`KI-AVG-001` |
| 每通道 AVG 剂量当量率 | `FP16` | 手册称平滑 mSv/h | 本设备 239/239 为 0；作为已知设备返回值接受；`KI-AVG-001` |

通道含义固定为：

- RAD0：伽玛；
- RAD1：中子；
- RAD2：PIN。

PIN 与其它传感器不能同时运行；有中子传感器的设备中，伽玛与中子绑定开启。读取到 `-1` 表示通道未运行，不是 0，也不是通信错误。

### 4.1 状态位

`RAD_SENSOR_STATUS`：

- bit 0-1：传感器选择，00 伽玛、01 中子、10 PIN；
- bit 2：RAD0 谱图累积；
- bit 3：RAD1 谱图累积；
- bit 4：RAD2 谱图累积。

`VOLUME_STATUS`：

- bit 0-1：全局音量，00 静音、01 小、10 大；
- bit 2：计数音；
- bit 3：按键音；
- bit 4：密集计数效果。

`LED_SCREEN_STATUS`：

- bit 0：计数闪光；
- bit 1：背光开关；
- bit 2：背光亮度，0 微亮、1 最亮；部分固件可能不支持调节。

本设备的 `BAT_PERCENT` 在 239 个正式窗口 A2 帧中均为 `0x80`，官方上位机同期显示 `0%`；因此实现只把低 7 位解释为百分比，并继续对 `101..127` 做越界保护。bit 7 在本设备持续置位，但现有证据只能确认它不是百分比的一部分，不能将其公开命名为“充电”“外接电源”或其它具体状态。

## 5. 设备信息包

`DEVICE_INFO` 总长 100 字节。`manual_v1_8_candidate` 对 96 字节 payload 使用以下隔离布局：offset 0-3 依次为型号、硬件版本、主固件版本和协处理器固件版本；offset 4-6 为三个传感器型号；offset 7-31 为 25 字节保留区；offset 32-47 为 16 字节设备 ID；offset 48 起为三个 16 字节累计块，每块依次为 `MC_RUNTIME`、`SUM_DOSE_TIME`、`SUM_DOSE`、`SUM_DOSE_EQ`。这个布局来自手册表格复核、独立固定向量和本设备重复 A5 读取；型号、版本、传感器与官方 UI 已逐项确认。D-012 根据 2026-09-06 用户确认保留原始累计单位 `mGy/mSv`，撤回此前只改微单位标签的推断；跨固件规则仍保持候选，此次裁定不等于新取得的抓包/物理量证据。

### 5.2 版本换算

- `HW_VER`：十进制值除以 10，例如 12 -> V1.2。
- `FW_VER`：十进制值除以 100，例如 180 -> V1.80。
- 手册对 `CO_FW_VER` 也给出 `/100` 示例；但本次实机 `CO_FW_VER` 原始值为 11，而同一设备官方上位机显示 `v1.1`。实现因此使用独立的协处理器版本格式化函数，仅把 `11 -> V1.1` 作为本设备已观察到的字段规则，不把它推广到其它固件；手册原文矛盾保留。

## 6. 谱图与自动上传

### 6.1 主动谱图

请求指定 `MC_DATA_SOURCE`：

- `0x00`：伽玛；
- `0x01`：中子；
- `0x02`：PIN。

响应片段包括：

- `MC_OFFSET`：首个道址；
- `MC_RATIO`：实际计数倍率，必须大于等于 1；
- 若干 16 位相对计数；实际计数为相对计数乘倍率。

手册给出 1024、2048、4096 三种总道数以及不同最大包长下的包数，但没有字段直接声明当前谱图总道数。最后一包超出实际范围的部分填 `0xFFFF`。

本设备 258 次有应答的主动谱图查询均返回 4 个 1033 字节 A0 帧，offset 固定为 0/512/1024/1536、ratio=1、每帧 512 道，共 2048 道；另有 3 次请求未返回任何 A0 帧，没有出现 1-3 帧的部分组。该规律达到本设备 L 级证据，但其它型号/固件仍不能只靠“遇到首个 0xFFFF”判断结束，因为手册没有保证 `0xFFFF` 不会成为合法相对计数；重组仍需联合设备能力、offset 集合、超时和事务代次。

### 6.2 自动上传流模式

开启自动上传后每秒一轮。低计数率时首个网络数据块由 81 字节 `STATUS_DATA` 后接一个 `STREAM_DATA` 组成；脉冲多时还有后续 `STREAM_DATA` 帧。

每个 16 位 `PULSE`：

- 高 2 bit：数据源；
- 低 14 bit：道址。

首块中 N 最大 473，后续流帧 N 最大 512。高计数率时设备改为谱模式，流数据 N=0。

### 6.3 自动上传谱模式

一轮包含一个 FLAG=`0xA3` 的状态帧和一组 FLAG=`0xA1` 的谱图片段。每轮只上传当前选中的一张谱图；选中项可能被本机或其它上位机改变。

实现证据：Coordinator 以 A3 的 `active_sensor` 开启新轮次，并按 source/offset 接受片段。旧实现只保留一个固定 2048 道缓冲；发布前补全候选改为按通道显式配置 1024/2048/4096 道，缺省 2048。片段可乱序到达，完全相同的重复片段不重复计数；source 不符、越界、重叠冲突、缺片、新一轮 A3 或断线都会使未完成组不发布。完整组复用现有 `SpectrumSnapshot`、A6 能量校准和 `_unrecorded_attributes` Recorder 边界；未知标志和 A4 不进入谱图语义路径。软件验证状态见 [PRE_RELEASE_COVERAGE.md](PRE_RELEASE_COVERAGE.md)，不提升为真实设备自动上传或新增道数的 L 级证据。

## 7. 校准数据

`CAL_DATA` 长 150 字节，包含工厂校准版本、能量缩放/偏移、触发阈值、剂量缩放、中子窗口、海拔偏移、自定义能量三次多项式和工厂分段能量多项式。

96 字节 payload 内的新增只读字段偏移为：`26 RAD0_TRIGGER_OFFSET` (uint16)、`28 RAD2_TRIGGER_OFFSET` (uint16)、`30/34/38 RAD0/1/2_DOSE_ZOOM` (float)、`42 NEU_WINDOW_CENTER` (uint16)、`44 ALTITUDE_M_OFFSET` (int16)。实现保留 `NEU_WINDOW_CENTER` 原名并以 `ch` 显示，不将其推断成注释中的 LOW/HIGH。

主要语义：

- 能量修正：`修正后能量 = ENERGY_ZOOM × 修正前能量 + ENERGY_OFFSET`。
- 自定义能量刻度为 `E(x) = ax³ + bx² + cx + d`。
- 2025 Q1 后设备通常使用三段工厂拟合；`FAC_CAL_VER=0x00` 单段，`0x02` 三段。
- 写校准支持全部字节为 `0xFF` 表示跳过对应字段。

由于字段存在文档矛盾，且错误校准会影响设备剂量计算，当前实现只允许用 `0x55` 读取 A6，不提供 `0x64` 写入口。本设备的最终上位机能谱导出与同期 A6 工厂校准参数完成离线复算：CSV 对应道址 77..2047，1971 个能量值按上位机两位小数逐点一致；这确认本设备的读侧布局与计算，但不授权任何校准写命令。

## 11. 证据 fixture 记录格式

后续测试 fixture 至少附带以下元数据：

- 采集日期与测试环境；
- 设备型号、主/协处理器固件、硬件版本；
- 传输类型、主机和端口的脱敏标识；
- 请求命令、SYNC、原始响应十六进制；
- 同时刻设备屏幕/官方上位机可见值；
- 已确认的端序、单位和误差范围；
- 是否存在自动上传、粘包、分片或并发客户端；
- fixture 中设备 ID 的脱敏方式。

fixture 不得包含 SSH 凭据、Home Assistant token 或可直接定位生产设备的网络信息。
