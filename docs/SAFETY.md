# KC761 安全模型

状态：`0.2.0-rc.1`

## 默认行为

新建或从旧版本升级的配置条目默认关闭设备控制和破坏性操作。默认可执行的设备通信仅包括读取：

| 命令 | 用途 | 默认可用 |
| --- | --- | --- |
| `0x52` | 获取完整谱图 | 是 |
| `0x53` | 获取实时状态 | 是 |
| `0x54` | 获取设备信息 | 是 |
| `0x55` | 获取校准数据 | 是，只读 |
| `0x62` | 设置设备状态 | 否 |
| `0x63` | 设置设备时间 | 否 |
| `0x64` | 写入校准数据 | 永久禁止，未实现 |
| `0x66` | 清空统计 | 否，且需第二层授权 |

谱图“刷新”是 `0x52` 读取；“保存谱图”和“导出 CSV”只操作 HA 本地快照/存档，不写设备。

## 两层写入门禁

Options Flow 提供两个独立布尔选项：

1. `enable_device_controls`：允许创建普通控制实体，并允许 `0x62`、`0x63`。
2. `enable_destructive_actions`：只有第一项同时开启时才生效，允许逐通道的 `0x66` 清空。

关闭第一项时，Options Flow 会把定时校时和破坏性操作一并归一化为关闭。协调器在真正编码/发送前再次检查门禁，所以旧前端、手工 WebSocket 请求或残留实体不能绕过后端授权。

启用普通控制后可能出现：

- 当前传感器、全局音量、背光亮度 select；
- 自动上传、按键音、计数音、密集计数效果、计数闪光、背光和每个已安装通道的谱图累积 switch；
- 立即同步设备时间 button；
- 可选的定时校时。

额外启用破坏性操作后，才创建逐通道的清空谱图、剂量曲线和累计剂量 button，谱图卡也才显示对应确认入口。

## 证据边界

- 读取字段有手册、模拟器和部分真实 TCP/BLE 证据，但仍只适用于已观察到的设备/固件组合。
- `0x62`、`0x63`、`0x66` 的集成实现已通过范围校验、ACK 回显、串行锁和模拟器测试；没有把模拟结果提升为实机写入证据。
- 协议档案、实体属性和诊断始终报告 `hardware_verified=false`。
- 不允许任意十六进制命令、任意校准值或 `0x64`。

## 多客户端风险

KC761 可能只能稳定服务一条 TCP 客户端，BLE、官方上位机和 HA 也可能竞争设备资源或互相改变全局状态。排障时先禁用 HA 配置条目，确认连接所有权；不要同时启动独立探针。RC 测试不应在生产设备上执行写命令。

## 隐私

默认诊断只保留版本、协议档案、连接/重连/帧错误计数、最近成功时间以及控制门禁状态。以下内容必须排除或脱敏：

- host、网络拓扑和完整 `DEVICE_ID`；
- 原始帧、完整谱图点阵和长期测量序列；
- Home Assistant token、SSH 凭据、私钥和本地私有路径。

谱图卡的可选浏览器诊断默认关闭，仅在当前 tab 的 `sessionStorage` 中保存有界、脱敏事件，并只生成本地下载。

## 生产门禁

在稳定版或生产部署前至少还需完成：

- 目标型号/固件的读侧字段和 BLE 服务复验；
- 对每个允许的写命令进行专门设备、逐字段读回和断电恢复测试；
- 自动上传开启态、多客户端竞争、通知丢包和 24 小时以上稳定性测试；
- 升级、卸载、回滚以及 Recorder 体积检查。

当前 RC 不授权任何生产环境写入。
